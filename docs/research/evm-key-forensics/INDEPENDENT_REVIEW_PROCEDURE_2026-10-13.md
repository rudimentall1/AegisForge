# Independent Review Procedure: Profanity `createSeed()`

Date: 2026-10-13
Scope: read-only source identity and cross-revision text comparison.

This procedure is for a reviewer who did not rely on the AegisForge report when checking the source. It does not ask the reviewer to build or run historical Profanity, derive wallet keys, or handle wallet material.

## 1. Prepare a clean checkout

Requirements: Git, Python 3.10 or newer. Run from a new temporary directory.

```sh
git clone --filter=blob:none --no-checkout https://github.com/johguse/profanity.git profanity-review
cd profanity-review
git fetch --depth=1 origin 0b54ffc86aafbb206675b4bfecb2ea09ac7a79f6
git fetch --depth=1 origin 186b9b27ab3e24a1899f648adcabcbf0e5f3131e
```

Record the OS, Git version, Python version, date, and whether the checkout was newly created.

## 2. Verify pinned Git objects without using the AegisForge extractor

Run these commands and compare their output to the expected identities below:

```sh
git rev-parse '0b54ffc86aafbb206675b4bfecb2ea09ac7a79f6^{commit}'
git rev-parse '0b54ffc86aafbb206675b4bfecb2ea09ac7a79f6:Dispatcher.cpp'
git rev-parse '186b9b27ab3e24a1899f648adcabcbf0e5f3131e^{commit}'
git rev-parse '186b9b27ab3e24a1899f648adcabcbf0e5f3131e:Dispatcher.cpp'
```

Expected Git blob IDs:

- Pre-disclosure `Dispatcher.cpp`: `c9226fc02a52633a84664cbf3aaf2b4af8a59b25`
- Post-disclosure archive `Dispatcher.cpp`: `884ced30ed6e55794ea5bda0451b52e81ddec1dd`

If any identity differs, stop and record the mismatch. Do not silently update the expected values.

## 3. Inspect the relevant function independently

Use Git's pinned objects to display the function context:

```sh
git show '0b54ffc86aafbb206675b4bfecb2ea09ac7a79f6:Dispatcher.cpp' | grep -n -A35 -B5 'cl_ulong4 Dispatcher::Device::createSeed()'
git show '186b9b27ab3e24a1899f648adcabcbf0e5f3131e:Dispatcher.cpp' | grep -n -A35 -B5 'cl_ulong4 Dispatcher::Device::createSeed()'
```

Reviewers should inspect the full function in both revisions, including preprocessor branches, and independently assess whether the extraction boundary used by the report is appropriate. The grep output is a navigation aid, not a proof of equality.

For a second, automated comparison, after obtaining the AegisForge repository separately, run its review helper against this checkout:

```sh
python tools/evm_key_forensics/independent_source_body_review.py --repo /absolute/path/to/profanity-review
```

Expected core result:

- `status`: `CHECKED`
- `same_function_body_bytes`: `true`
- `function_body_bytes`: `357` for both revisions
- `function_body_sha256`: `897d89b20fc71072543bb5aa4538c4dfb17c77e81eab5d2af2f749fb1563859c` for both revisions
- `conclusion`: `INCONCLUSIVE`

The helper is intentionally a small byte-oriented extractor, not a complete C++ parser. A reviewer should not treat running it as the independent manual review itself.

## 4. Review the claim and its limits

The narrow supported observation is that the extracted `createSeed()` function body is byte-for-byte equal in these two pinned source revisions. The visible source pattern initializes `std::mt19937_64` from one call to `std::random_device` and then obtains four distribution outputs from that engine.

This does **not** establish:

- the effective entropy of the seed on any historical runtime;
- predictable private keys or exploitability;
- whether a particular binary was built from either source revision;
- whether a particular wallet was generated by affected code or is exposed;
- that the historical vulnerability has been reproduced.

No historical application build or execution is required for this review.

## 5. Reviewer record

A reviewer completing this procedure should publish or attach a record containing:

- reviewer identity or public review handle;
- date and environment;
- exact commands used and unedited outputs;
- whether both Git object identities matched;
- whether the full function bodies were manually inspected;
- any discrepancy, ambiguity, or limitation;
- explicit decision: `CONFIRMED_SOURCE_TEXT_ONLY`, `DISAGREE`, or `UNABLE_TO_VERIFY`.

Do not mark the review independent if it only repeats the AegisForge helper output. Keep the overall research conclusion `INCONCLUSIVE` unless separate, sufficient evidence supports a stronger conclusion.
